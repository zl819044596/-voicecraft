# 核心功能规格（CORE-FEATURES）v1

> **状态**：核心功能（用户 2026-08-12 确认："这是我的核心功能"）
> **权威性**：本文档为产品需求的上位定义，所有相关开发以此为准；与旧实现冲突时**以本文档为准，不沿用旧逻辑**（"不要引用以前的，以前就不对，就是因为不对才重新写的"）。

---

## 一、三种文案生成方式（主方向核心功能）

| # | 方式 | 说明 |
|---|------|------|
| 1 | **直接填写** | 用户手工填写文案 |
| 2 | **已有文案二次重构** | 基于已有文案重写/重构，**重构规则可配置** |
| 3 | **商品生成文案** | 输入一个商品，自动生成文案 |

> 三条主方向，是产品的核心入口。

## 二、两种工作流

### 流程 A（静态图流程）
```
文案（可以再次修改）
  → 把文案拆分（拆分规则可配置），生成的每条可以修改
  → 根据拆分的文案生成图片，每张也可以修改（生成规则可配置）
  → 根据拆分的文案生成语音，每条也可以修改
  → 合成视频
  → 下载（每个环节的产出 zip 包）
```

### 流程 B（图生视频流程）＝ 流程 A + 图片→视频
```
文案（可以再次修改）
  → 把文案拆分（拆分规则可配置），生成的每条可以修改
  → 根据拆分的文案生成图片，每张也可以修改（生成规则可配置）
  → 根据每张图片生成视频，也可以修改（生成规则可配置）
  → 根据拆分的文案生成语音，每条也可以修改
  → 合成视频
  → 下载（每个环节的产出 zip 包）
```

## 三、可配置规则（关键能力）

| 规则 | 作用环节 | 说明 |
|------|---------|------|
| **重构规则** | 文案二次重构 | 决定"已有文案 → 新文案"的改写方式 |
| **拆分规则** | 文案拆分 | 决定文案如何拆成多条（每段一个镜头）|
| **生成规则（图片）** | 文案→图片 | 决定每张图的画面生成方式 |
| **生成规则（图生视频）** | 图片→视频 | 决定每个视频片段生成方式 |

> 所有规则用户可配置、可保存、可选用（具体 UI 与存储设计见实施设计文档）。

## 四、每环节产出与下载（zip 包）

| 环节 | 产出 | 下载 |
|------|------|------|
| 文案（最终版）| 文案文本 | zip |
| 拆分结果 | 每条文案 | zip |
| 图片 | 每张图 | zip |
| 图生视频片段 | 每段视频 | zip |
| 语音 | 每条语音 | zip |
| 合成视频 | 成片 | zip |

> 每个环节的产出都应有 zip 包可下载（不仅仅是最终成片）。

## 五、与现有 V3 流水线的对应

| 核心功能环节 | 现有流水线 | 差距 |
|-------------|-----------|------|
| 直接填写文案 | quick text 入口 | ✅ 已有 |
| 二次重构 | quick creative 入口 | ⚠️ 重构规则不可配 |
| 商品生成 | quick 商品选择 | ⚠️ 确认链路完整性 |
| 拆分 | L3 分镜（预设 chips）| ⚠️ 拆分规则不可配（固定预设）|
| 单条修改 | 单镜编辑/重生成 | ✅ 已有 |
| 图片生成 | L4 生图 | ⚠️ 生成规则不可配 |
| 图生视频 | i2v 模式 | ⚠️ 生成规则不可配 |
| 语音 | L5/L6 配音 | ✅ 已有（每条可改）|
| 合成 | L6/L7 合成 | ✅ 已有 |
| 每环节 zip | 仅最终导出 | ❌ 缺（每环节 zip）|

## 六、实施优先级（建议）

1. **P0**：规则可配化（重构/拆分/图片/图生视频规则 CRUD + 各环节应用）
2. **P0**：每环节 zip 导出（文案/拆分/图片/视频/语音/成片）
3. **P1**：商品生成文案链路补全
4. **P1**：两种工作流（A/B）在快速生成页的显式选择
