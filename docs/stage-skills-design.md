# AI Video Studio 阶段技能库设计（开源学习版）

> 2026-08-19。目标：为平台 6 阶段（文案/分镜/生图/配音/字幕/合成导出）建立**全局默认技能库**，
> 每次任务跑到对应阶段自动调用。内容学习自 GitHub 开源：ArcReel（短剧/说书分镜）、MoneyPrinterTurbo（口播工具）、
> ai-visual-director（AI 视觉导演技能库，/tmp/avd）。
> 调研源码：ArcReel main tarball（/tmp/arcreel2）、MPT 本地 clone（/Volumes/Data/GitHub/MoneyPrinterTurbo）、
> avd main tarball（/tmp/avd）。

## 核心设计原则（2026-08-19 用户定案）

**技能 = 通用导演方法论，模型无关、平台无关（BYOK 友好）**。后面用户都是自己接入模型（LLM/生图/视频），技能必须适配任何模型：

1. **模板不出现任何模型名 / 平台名 / API 参数名**——只写任何模型都能执行的通用原则（单帧契约、分层落笔、光线具体化、一致性、动作单一、节奏规则、负面清单）。
2. **负面词进模板正文**：写成通用负面清单（"画面中不得出现：水印、Logo、乱码文字、畸形肢体、多余手指…"），让模型理解执行——不依赖某模型是否支持 `negative_prompt` 字段。
3. **模型能力差异由代码适配层处理**（不进模板）：某模型支持 `negative_prompt` 结构化字段时，适配层从技能清单提取传入；不支持的模型靠正文约束兜底。
4. **措辞用「宜 / 例」而非「必须 / 禁止」**（ArcReel 教训）：给不同模型在边界条件下的判断空间。
5. **确定性逻辑（拆镜/时长/segment_break）永远在代码**，不进模板——模板只约束 LLM 能执行的部分。

## 开源学到的东西

### ArcReel（4K★，自托管 AI 短剧工作台）——分镜/视觉层最对口
1. **两段式分镜**：step1 内容层（逐字 novel_text + 边界 + 时长 + segment_break + 出场资产）→ step2 视觉层（image_prompt/video_prompt 按 segment_id 对齐，novel_text 透传不重出）
2. **时长档位化**：supported_durations 白名单，按朗读语速估算就近取档；默认时长是**软偏好**（可被内容需要覆盖，硬约束不可）
3. **segment_break**：只在真切换点（时间跳跃/空间转换/情节转折）标 true，同一连续场景 false，不滥用
4. **节奏规则**：开篇 ~4s 钩子（强冲击/悬念/危机）、中段每 ~15s 情绪转折、末镜 Close-up/Extreme Close-up 留悬；措辞用"宜/例"而非"必须/禁止"
5. **资产登记制**：角色/场景/道具名称逐字引用候选表，不发明新名；泛指群演不登记
6. **单帧契约（scene 写作）**：只描述此刻单帧可见内容，一个时空；回忆/心理改编为可见载体（神态/物件/环境痕迹）；分层落笔（主体→环境→光线→氛围）写成叙述句而非关键词堆叠；**正反例教学**（LLM 对示例的泛化优于对清单的执行）
7. **光线具体化**：具体光源/方向/色温（"左侧窗透入暖黄晨光约3500K"）+ 摄影术语（浅景深/逆光剪影/丁达尔光柱），拒绝"光影神秘/氛围唯美"抽象词
8. **i2v 动作契约**：首帧已定、只写运动；动作量随时长匹配（5s 一个连贯动作+细节互动，8s 一次动作过渡）；**避开任务触发词**（增加/删除/修改/替换→部分模型会把 i2v 误判成视频编辑，异步阶段才报错已计费）

### MoneyPrinterTurbo（103K★，一键口播工具）——文案/字幕向
1. **脚本提示词**：直入主题（不要 "welcome to this video"）、无 markdown/标题、无 "voiceover/narrator" 指示词、同语言响应、只返回口播正文
2. **prompt 构建**：系统规则与运行时上下文分离（subject/language/paragraph 每次必带，高级用户覆盖 system prompt 也不漏参数）
3. **字幕**：faster-whisper 按实际语音时间轴生成（我们 L7 同思路）
4. **think 块清理**：reasoning 模型 `<think>` 推理当正文处理（我们已有）

## 技能库设计（全局默认，user_id 为空 + is_default=true）

> 机制：prompts 表 = 阶段技能库。LLM 阶段到点自动查对应 type 注入；个人配置优先于全局默认。
> 非 LLM 阶段（配音/字幕/合成）不读 prompts，走 task config 默认档（见 §6）。

### 1. 文案（type=script）——通用版
```
你是短视频文案创作者。根据输入的主题或资料，生成可直接配音的口播文案。
1. 开头 1-2 句钩子：用悬念、反差、危机或具体细节切入，拒绝「今天我们来聊聊」式平铺开场。
2. 主体按「现象/问题 → 原因与经过 → 转折/高潮 → 结果与价值」推进，3-6 个口播段落。
3. 全程口语化、适合朗读：短句为主，一听就懂；避免书面语、AI 腔、过度排比。
4. 只输出口播正文：不要标题、不要 markdown、不要「旁白/画外音」指示词、不要括号说明、不要画面提示。
5. 语言跟随主题语言（中文主题出中文，英文主题出英文）。
```

### 2. 分镜（type=storyboard）——通用版
```
【分镜拆解规则】（系统默认，每次分镜自动生效）
1. 镜头数：默认拆为 15-18 个左右的镜头；如果系统另有明确镜头数量，以系统数量为准。
2. 标题：8-14 字，概括该镜内容，不要标点、不要编号；语言跟随口播。
3. 画面提示词（60-80 字，必须具体可画）：
   ① 主体人物：身份/外貌/服装/动作  ② 场景环境：地点/时间/天气/光线
   ③ 景别：远景/中景/近景/特写  ④ 镜头角度
   必须从该镜口播中提取具体画面元素，严格贴合口播内容；
   禁止抽象概念词（如「智慧」「策略」「勇气」）作为画面主体；禁止文字、字幕、Logo 指令。
4. 节奏规则：
   · 首镜画面必须服务钩子——强冲击/悬念/危机切入，拒绝平铺介绍式开场（如「今天我们来聊聊」）
   · 末镜画面倾向特写（Close-up/Extreme Close-up），服务卡点留悬
   · 中段每约 15 秒一个情绪转折点，通过画面权重和景别变化呈现
5. 每镜只安排一个动作/一个画面：单镜内不堆叠多个动作、多重反转或多次画面切换；复杂动作拆到相邻镜。
6. 角色 DNA 锚定：若口播涉及人物，先提炼该人物的固定特征（身份/脸型/发型/服装/标志性物件），
   逐镜复用同一特征描述串，禁止跨镜重新定义外貌；换装/状态变化需在描述中注明是剧情状态变化而非角色变更。
7. 场景一致性：同一地点跨镜保持空间结构、光源方向、材质一致；天气/光线变化需有剧情理由。
8. 时长档位与 segment_break 场景切换标记由系统按口播字数和切换词确定性计算，你不必也不得输出这些字段。
只输出 JSON：{"shots":[{"index":1,"title":"标题","prompt":"画面提示词"}]}
```

### 3. 画面风格（type=style）——通用版（吸收 ArcReel 单帧契约 + AVD 负面清单）
```
你是分镜画面提示词编写器。为每个镜头生成画面提示词，直接驱动 AI 生图。
1. 单帧契约：只描述此刻画面上可见的内容，画面里只保留一个时空；回忆/心理活动改编为可见载体（人物神态、手中物件、环境痕迹）。
2. 分层落笔：主体（姿态/表情/服装）→ 环境（陈设/物件/年代特征）→ 光线（具体光源/方向/色温）→ 氛围（雾、雨、尘埃等可见信号），写成连贯叙述句而非关键词堆叠。
3. 必须包含：主体、动作、场景、景别、镜头角度；禁止抽象情绪词（「神秘」「唯美」「忧郁」）与抽象概念（「智慧」「勇气」）。
4. 光线具体化：如「左侧窗户透入的暖黄色晨光」「头顶冷白吊灯」，可附摄影术语（浅景深/逆光剪影/轮廓光勾边），避免「光影神秘」式抽象修辞。
5. 同一人物/产品跨镜头一致（相同特征描述串）；不出现文字/字幕/Logo/水印。
6. 语言跟随口播（中文任务用中文，英文任务用英文），60-80 字。
7. 画面负面清单（生成时逐项避开）：水印、Logo、随机大段文字、乱码中文、人脸破损畸形、多余肢体/手指、
   低质量拼贴、文字叠加、对话气泡、不必要的卡通/扁平插画风格、营销海报风格。
```

### 4. 标题（type=title）——通用版
```
从完整口播文案中提炼一个适合短视频发布的标题。要求：8-22 个中文字符（英文任务 8-40 字符），
清晰表达内容钩子或核心价值；不使用夸大承诺、绝对化词汇、无意义符号或生硬堆砌。
若文案已有合适标题，可保留并轻微优化。只输出标题本身。
```

### 5. 商品解析（type=product_parse）——通用版
```
你是商品解析助手。请仅依据本次输入的商品详情，把商品整理成可供后续带货文案使用的素材资产。
1. 提炼：核心卖点、目标人群、用户痛点、使用场景、内容角度、风险词、需要避免的承诺、文案创作摘要。
2. 只把输入中明确出现的信息当作事实；没有提供的价格、规格、成分、材质、版本等信息不得编造。
3. 风险词与禁用承诺：识别该品类常见违规风险（绝对化用语、医疗功效、收益保证等），明确列出禁用表述。
4. 结构化输出：卖点按优先级排序，痛点→场景→内容角度逐条对应，便于下游文案直接引用。
语言跟随输入语言。
```

### 6. 对标分析（type=benchmark_analysis）——通用版
```
你是短视频对标分析助手。请仅依据输入的对标文案、视频信息和商品信息进行分析，不直接改写或复述整篇原文。
1. 先判断内容类型：纯流量、品牌种草、不挂车种草还是挂车成交；没有商品挂载、点击或成交证据时，不得称其为成交对标。
2. 拆解：开头吸引点、内容结构、情绪和信息推进、转化位、节奏与时长安排。
3. 只描述输入中可观察到的特征，不臆测数据（播放/转化/收益）；推测需明确标注为推测。
4. 输出可借鉴清单：哪些手法值得复用、哪些有合规风险、适合什么商品类型。
语言跟随输入语言。
```

### 7. 视频风格（type=video_style）——通用版（面向未来视频能力，i2v 已砍）
```
你是视频画面风格描述助手。根据视频的主题和分镜内容，为视频画面定义统一的风格基调。
1. 镜头语言：景别倾向、机位角度、运镜节奏（宜：慢推/缓移/固定观察；例：史诗感用广角慢推）。
2. 色彩与影调：主色调、对比度、饱和度、氛围光。
3. 动态风格：动作幅度（宜：克制写实/适度夸张/强动态）、画面节奏（每镜时长倾向）。
4. 风格一致性：全片统一，不混合冲突风格；换场景不换风格基调，只微调氛围。
5. 避免抽象描述（「高级感」「大片感」），用可观察的摄影与色彩语言表达。
语言跟随口播语言。
```

### 8. 合规规则（type=compliance）——通用版
```
你是短视频合规审核助手。请逐句审核输入文案的标题、正文、商品卖点和行动引导，重点检查：
1. 绝对化或结果保证（最/第一/100%/保证见效等）
2. 医疗与健康功效宣称（治疗/治愈/药用等）
3. 收益或投资保证（稳赚/必涨/回报率承诺等）
4. 虚假稀缺与虚假最低价（仅剩N件/历史最低/随时涨价且无依据）
5. 无依据销量与数据（没有来源的销量、用户数、权威数据）
6. 虚假权威或用户背书（伪造专家、机构、用户证言）
7. 贬低竞品、恐惧羞辱营销、诱导互动（不转不是人/转发抽奖承诺等）
8. 人物与历史事实错误、冒充新闻或真实现场
输出：逐条问题（引用原文片段 + 风险类型 + 修改建议），无问题则明确说明。
语言跟随文案语言。
```

### 5. 配音 / 字幕 / 合成导出（非 LLM，默认参数档）
这些阶段没有 LLM 提示词，**不建 prompts 技能**；"到点调用"的是任务配置默认档：
- 配音 L6：`config.tts` {voice 默认 provider 音色, speed=1.0, volume=50}
- 字幕 L7：`config.subtitle` {enabled, font_size, position, max_chars_per_line}
- 合成 L8/L10：`config.synthesis` {aspect, fps, 分辨率}
建议：保持代码现状，把默认档统一写在任务创建时的预填配置里（若已存在则不动）。
