## 2. 本轮（第 4 次交接）实读发现并修复的问题

### 2.1 【严重】三大数据页静默空数据（apiFetch 契约错用）

`src/lib/api-client.ts` 的 `apiFetch` 返回**已解析 JSON**（非 Response；非 2xx 抛 `ApiRequestError`、204/空体返回 null），但以下页面还按旧模式 `res.ok`/`res.json()`/`data.classes` 使用 → 数据静默为空：

- **app/page.tsx（工作台）**：4 个 `Promise.allSettled` 改泛型直接读 `.items`；model-configs 从 `{items}` 扁平建 byId（删未用的 `MODEL_CLASSES` 常量，`CLASS_LABEL` 保留）；详情 enrich 改 `apiFetch<{config}>` 直接 await。另修一处注释吞掉 `const CLASS_LABEL` 声明的语法错误。
- **tasks/page.tsx**：同款改法；补 `ModelConfig` 类型导入、删未用的 `MODEL_CLASSES`。
- **projects/page.tsx**：`apiFetch<{items: ProjectRow[]}>` / `apiFetch<{items: TaskRow[]}>` 直接读 items。

### 2.2 tasks/new 支持 `?product=` 参数（体验缺口补上）

products 两页的「保存并新建任务」都跳 `/app/tasks/new?product=:id`，但 tasks/new 之前完全忽略该参数。已按 benchmarks/new 的 `editIdFromLocation` 同法实现：`useRef(productIdFromLocation())` 读 `window.location.search`（避开 useSearchParams 的 Suspense 问题），products 加载后自动选中该商品并填入 source_text。

### 2.3 其余页面复查结论（本轮逐页 Read/Grep）

- **profile**：纯静态（useAuth 取昵称），无 API 调用，✅。
- **projects/[id]**、**tasks/[id]**：均为 WizardPage 薄包装，✅。
- **login**：`apiFetch` 调 `/api/auth/magic-link|verify|google`，与 auth.js 实际端点一致，✅。
- **残留旧模式扫描**：`grep res\.ok|res\.json\(\)|data\.classes|data\.benchmarks|data\.products` 全站仅两处命中，均为**正确用法**（`src/app/api/report-abuse/route.ts` 是 Next route handler 转发原生 Response；`quick/page.tsx` 的 `handlePreview` 用 `apiRaw` 取 blob，音频流预览）。
